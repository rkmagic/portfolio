## Context

Having worked on mobile apps for a long time, this challenge felt like home. We built it for a Tech Challenge run by my university's Google Developers Club and reached the [final](https://www.linkedin.com/posts/vaibhavtyagi8_gdgoncampus-buildwithai-techroulette-activity-7455253555768340482-xxpZ) hosted at Google's Madrid office (with MBA peers Vaibhav Tyagi and Patricio Villar).

A gamified sleep product where going to bed on time is the sport. The web app owns leagues, leaderboards, the live world map, and Gemini-written "obituaries" when a streak dies. The Android app is the companion that makes the sport hard to cheat: it verifies sleep on-device and pushes presence into the same Firebase project the web reads.

Repo: [rkmagic/dormia_app](https://github.com/rkmagic/dormia_app). Deck with the full product story is embedded below.

## Problem

Every app on your phone is built to keep you awake. Knowing you should sleep is easy. Stopping work, study, or scrolling is hard, especially alone, when bedtime is negotiable.

Sleep trackers already exist. What they do not create is stakes. Without competition, social presence, and a verification layer that is not "I tapped a button," sleep goals stay optional. Wearables raise the bar, but we wanted something that works with the phone people already carry.

## Process

We split the product: web for the game loop (targets, leagues, map, obituaries), Android for ground truth.

On Android the job was narrow but non-negotiable:

- Sign in with Google so identity matches the web player (Firestore)
- Run background sleep detection via Google Play Services Sleep APIs (classify + segment events), with manual Fall Asleep / Wake Up as a fallback
- Detect location (GPS first, IP fallback) so the live map can place the player by city / country / continent
- Keep field names aligned with the web client so sleep state and presence update in near real time.

Firebase is at the core of this application and its amazing how real-time database works.

Permissions were part of the product, not an afterthought: activity recognition, location, notifications (Android 13+), and a foreground service for continuous tracking. Without them, automatic detection collapses. Below is a screenshot of real-time data tracking from the app, with manual buttons for quick testing.

**Stack:** Kotlin, Jetpack Compose, AndroidX Navigation + ViewModel, Firebase Auth + Firestore, Google Sign-In, Location Services, Google Sleep API.

## Outcomes

The APK ships the verification half of this project. When a player falls asleep or wakes, Firestore updates and the web live view can reflect it without trusting a checkbox. The broader product does the rest: private leagues with invite codes, city/country/world rankings, a weekly pool that rewards the best sleepers, and public streak-loss obituaries.

## Future Work

We could improve this further by:
- Designing a cleaner UI. The current one was built to demonstrate the capability.
- Tightening the Android ↔ web contract further (schema versioning when fields change).
- Improving confidence handling from Sleep API scores so borderline nights are less noisy on the leaderboard.
