## Context

Personal side project, started March 2026. I had long recordings from meetings, interviews, and voice notes. I needed a quick and easy solution that could turn a 1 hour voice recording into notes without buying another SaaS subscription.

The repo is public: [rkmagic/stt_simple_asap](https://github.com/rkmagic/stt_simple_asap).

## Problem

I record many meetings/conversations/interviews using my phone microphone, so that I could convert it into notes, purely for self-reference and self-reflection. The duration of these recordings lasted anywhere from 20 mins to more than an hour. LLM chat tools rejected the files as too large. Consumer transcription sites did the same, or they were priced like a product I was not going to pay for occasional personal use. OpenAI Whisper was cheap enough to run myself, but the API caps uploads at about 25 MB - which most of my recordings exceeded.

The real job was not “call an API.” It was: drop in several messy audio files, wait without guessing if it hung, and walk away with transcripts I could copy, download, or zip.

## Process

I scoped it as a local Node app first: upload UI, Whisper on the server, text I could review in the browser. FFmpeg was the non-negotiable dependency for anything over the size limit - `ffprobe` for duration, `ffmpeg` to split with stream copy so I was not re-encoding hour-long files. It took some iterations for FFmpeg to correctly work on the server but kudos for the developers of this amazing piece of software.

Once that worked, I then automated the process of having to drop the recording from my phone into this node app.

I created an API for the node app that can take recordings. Hosted on Render with an optional bearer `API_KEY` so I could put it on a public URL without anyone burning my OpenAI key. Then followed a simple n8n workflow that can take files from a google drive and output the transcribed notes back into a google drive. This runs on my laptop using docker.

I initially tried to create the worklflow using Make but there were issues. Multipart field names were inconsistent (`files` vs `file` vs `audio` vs `audio_file`), extra file parts overloaded file handling, and Telegram “.m4a” voice notes were actually 3GPP (`ftyp 3gp4`) that Whisper rejects. Those are now remuxed to AAC in MP4 before the API call.

![n8n-workflow](/images/n8n_meeting.png)

The n8n workflow is a simple one. There is a timer added to wake up the render server as its on sleep if unused.

**Final Stack:** Node.js, Express, n8n, OpenAI Whisper API, FFmpeg/ffprobe, Docker, Render

## Outcome

I am now able to transcribe many recordings of long duration withins a few cents ($0.006/minute) without paying monthly SaaS subscriptions. 

Future work can include connecting the transcribed .zip file with the .txt files to a Claude API which uses a skill.md file to output a final summary of notes in .md format. I currently do this manually with a skill on my Claude app to avoid paying again for Claude API tokens. These .md notes could also automatically be fed into a knowledge base for retrieval.
